# Enterprise Core v1.0.2

Windows Demo Setup Foundation

## Summary

Enterprise Core v1.0.2 strengthens the project as a local-first platform by adding a practical Windows demo setup path, a future Windows installer strategy, safe preflight validation, and a seeded demo administrator for fresh local installations.

This release keeps a clear boundary between current technical demo support and future production installer behavior.

## Highlights

- Windows demo setup guide.
- Windows local installer strategy.
- Demo startup helper.
- Preflight checker.
- Admin demo user seeder.
- Troubleshooting learned from a clean Windows setup.
- Successful second-machine validation.

The Windows demo setup guide is available at:

## Windows Local Installer Direction

The future Windows installer direction is documented at:

- [Windows Local Installer Strategy](../architecture/Windows%20Local%20Installer%20Strategy.md)

That strategy describes a future `Enterprise-Core-Setup.exe`, local runtime, launcher, local PostgreSQL usage, backup and restore direction, updates, and licensing or membership validation.

This is future strategy only. Enterprise Core v1.0.2 does not include a production Windows installer.

## Demo Runtime Scripts

This release includes Windows demo startup helpers:

- `scripts/windows/start-enterprise-core.ps1`
- `scripts/windows/Start Enterprise Core.bat`

The helper starts the Laravel backend and Next.js Admin Web in separate PowerShell windows, then opens Admin Web in the default browser.

Both PowerShell windows must remain open. Closing either window stops that part of the local demo runtime. This is expected for the demo helper.

A future installer or Windows service runtime should manage local services differently.

## Preflight Checker

This release includes a safe Windows prerequisite checker:

- `scripts/windows/check-enterprise-core-prerequisites.ps1`
- `scripts/windows/Check Enterprise Core Prerequisites.bat`

The checker validates:

- Git.
- PHP.
- Composer.
- Node.
- npm.
- Required PHP extensions.
- PostgreSQL service status.
- `psql` availability.
- Backend and frontend folders.
- Backend `.env`.
- Admin Web `.env.local`.
- Backend `vendor`.
- Frontend `node_modules`.

Safety boundaries:

- It does not install dependencies.
- It does not modify files.
- It does not modify databases.
- It does not run migrations.
- It does not start services.
- It does not print secrets.

## Fresh Demo Admin

Enterprise Auth Service now includes `AdminUserSeeder`.

After running:

```bash
php artisan migrate --seed
```

a fresh local or demo installation creates an active demo administrator:

```text
Email: admin@example.com
Password: password123
Role: Administrator
```

These are demo credentials only. Change them for any non-demo environment.
