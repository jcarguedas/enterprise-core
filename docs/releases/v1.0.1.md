# Enterprise Core v1.0.1 Release Notes

## Release Summary

Enterprise Core v1.0.1 is an early foundation release for a portfolio-grade modular enterprise platform.

This release improves the Admin Web experience, completes several localization and access UX details, introduces an informational product version label, and documents future architecture direction.

Enterprise Core is not a complete ERP in this release. Business modules such as customers, inventory, sales, reporting, invoicing, and AI-assisted operations remain future roadmap areas.

## Highlights

- Runtime light and dark theme switching.
- Runtime English and Spanish language switching.
- Public landing and login page localization.
- Protected dashboard localization completion.
- Read-only Roles page.
- Permission-aware navigation and dashboard actions.
- Reusable access-denied state.
- Toast notifications for successful admin workflows.
- Product version display as `Enterprise Core v1.0.1`.
- Localized known backend/API error messages.
- Password show/hide controls for login and create user workflows.
- Protected read-only System Info page.
- Architecture documentation for local-first, command-center, and release/update strategy directions.

## Admin Web

Admin Web continues to serve as the protected Next.js administration interface for Enterprise Core.

Current Admin Web capabilities include:

- Public landing page.
- Login page.
- Protected dashboard.
- Users module.
- Read-only Roles page.
- Protected System Info page.
- Runtime language switching.
- Runtime theme switching.
- Toast notifications.
- Permission-aware sidebar navigation.
- Permission-aware dashboard actions.

The System Info page is informational only and does not perform update checks.

## Authentication and Access UX

This release improves the protected administration experience around authentication and access control.

Included UX improvements:

- Dashboard account summary.
- Inactive account handling.
- Reusable `AccessDeniedState`.
- Navigation that hides permission-gated sections when the current user does not have the required permission.
- Dashboard actions that respect available permissions.

Administrative authorization remains enforced by the backend. Frontend permission-aware UI is a usability layer, not the final security boundary.

## Localization

Runtime English and Spanish switching is available across the public and protected Admin Web surfaces included in this release.

Localized areas include:

- Landing page.
- Login page.
- Dashboard.
- Users workflows.
- Roles page.
- System Info page.
- Known backend/API error messages.

Known localized API/backend errors include invalid credentials, inactive account, required name/email/password fields, duplicate email, password minimum length, and password confirmation validation.

Unknown backend messages are preserved as fallback text.

## Product Versioning

Admin Web now displays:

```text
Enterprise Core v1.0.1
```

The version label is informational. It does not currently check for updates, validate release eligibility, download packages, apply updates, or run migrations.

## System Info

The protected System Info page displays read-only product and runtime information:

- Product display name.
- Product version.
- Admin app name.
- API base URL.
- Authentication provider.
- Update mode/status.
- Deployment model direction.

This page reinforces version visibility and future update strategy without implementing update distribution.

## Architecture Documentation

This release adds and links architecture documentation for future platform direction:

- [Local-First Enterprise Core](../architecture/Local-First%20Enterprise%20Core.md)
- [Enterprise Command Center](../architecture/Enterprise%20Command%20Center.md)
- [Release and Update Strategy](../architecture/Release%20and%20Update%20Strategy.md)

These documents describe planned architecture direction, not completed implementation.

The documented direction includes:

- Local-first customer deployments where operational data stays local by default.
- Optional cloud services limited to licensing, subscription status, update metadata, and product distribution.
- A future operational command center using safe known commands before AI-assisted execution.
- A future release/update strategy with semantic versioning, metadata, migration warnings, customer-controlled updates, and backup expectations.

## Validation

Frontend validation commands used for Admin Web changes:

```bash
cd apps/enterprise-admin-web
npm run lint
npm run build
```

Backend validation command for backend changes:

```bash
cd services/enterprise-auth-service/src
php artisan test
```

Do not assume backend tests were run for a documentation-only or frontend-only release note update unless the specific task records that validation.

## Known Limitations

- Enterprise Core v1.0.1 is a foundation release, not a complete ERP.
- Update checking and update distribution are not implemented.
- The product version label is informational only.
- No customer, inventory, sales, reporting, invoicing, or command-center business modules are implemented as complete product modules.
- No AI command execution is implemented.
- No cloud licensing service is implemented.
- No backup, restore, export, or import workflow is implemented.
- No automatic customer deployment upgrade flow is implemented.

## Upgrade Notes

No automated upgrade workflow exists for this release.

For local development, pull the relevant code changes, install dependencies as needed, and run validation commands for the area being changed.

Future update workflows should be customer-controlled, especially when database migrations are involved. Migration-based upgrades should include backup guidance, compatibility notes, and health verification before being considered production-ready.
